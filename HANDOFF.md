# finance_bot — Engineering Handoff

A complete guide to rebuild and operate this system. If you read this top to
bottom and run the commands, you will end up with exactly what exists today.

> **What this is:** a modular research engine that ingests price + news data,
> links stocks into a correlation/lead-lag "mind", backtests **without
> lookahead**, and emits a long-term `+1 / ~0 / −1` conviction index per stock —
> plus a daily driver that nudges each index from the day's metrics, and a
> screener that finds strong long-term names currently dipping.
>
> **What this is NOT:** it never places trades, never moves money, and gives no
> personalized investment advice. Every number is a **model output**. A human
> reviews and places any order. These boundaries are load-bearing — keep them.

---

## 1. The idea in one paragraph

Every stock gets a **structural long-term index** in `[−1, +1]` built from four
price-derived components (trend, momentum, stability, news-tilt). That's the
slow "thesis." On top of it sits a **daily driver** that adds/subtracts a small
amount each day from that day's metrics, with a pull back toward the structural
anchor so noise can't corrupt the thesis. The **long-term view is kept strictly
separate from the short-term tape** — which is what lets the screener find the
key setup: *strong long-term thesis, weak right now* (a dip to lean into vs. a
falling knife).

## 2. Prerequisites & setup

- **Python 3.11** (developed on 3.11.4, miniconda).
- Dependencies (all common, pip-installable):
  ```bash
  pip install pandas numpy scipy yfinance requests pyarrow matplotlib
  ```
  Only the standard scientific stack + `yfinance` (Yahoo market data) +
  `pyarrow` (Parquet). No networkx/feedparser — the graph is plain JSON and the
  RSS parser is stdlib `xml.etree`.
- **No API keys required** for what ships (public Yahoo + BBC RSS). Paid feeds
  are optional extensions (see §9).
- `data/` is git-ignored and regenerated by the pipeline.

Run everything as a module from the repo root:
```bash
python -m finance_bot.cli <command>
```

| File | Shape | Written by |
|------|-------|-----------|
| `prices/<T>.parquet` | index=`date`, cols `Close,High,Low,Open,Volume,ticker` | `ingest/prices.py` |
| `news/events.jsonl` | one JSON `NewsEvent` per line (id, ts, source, headline, tickers, themes, prior…) | `ingest/news.py` |
| `graph/mind.json` | `{meta, nodes:{ticker:{themes}}, edges:[{src,dst,kind,weight,lag}]}` | `mind/graph.py` |
| `profiles/<T>.json` | one profile (see §6.5) | `profile.py` / `daily.py` |
| `profiles/_summary.csv` | `ticker,bucket,index,structural,daily_delta,last_close,themes` | `profile.py` / `daily.py` |
| `profiles/_daily_state.json` | `{ticker:{live_index,structural,last_date,last_delta}}` | `daily.py` |

| `profiles/_dip_candidates.csv` | ranked screener rows | `screen.py` |

All timestamps are point-in-time: news keeps the exact publish time so the
backtest can replay history without leaking the future.

## 5. The pipeline — commands & order

```bash
# Step 1 — download 5y OHLCV for the whole universe (idempotent, cached 1 day)
python -m finance_bot.cli download            # or --sample for 8 tickers, --force, --period max

# Step 2 — build the correlation / lead-lag "mind"
python -m finance_bot.cli graph

# Step 3 — collect news events (public RSS)
python -m finance_bot.cli news                # or --sample

# Step 4 — event study + one walk-forward backtest
python -m finance_bot.cli backtest --ticker PLTR

# Step 5 — build the structural long-term index for all names
python -m finance_bot.cli profile

# ---- added on top of the 5-step directorate ----
# Daily driver — nudge each index from today's metrics (run every trading day)
python -m finance_bot.cli daily --download    # --download refreshes prices first

# Screener — strong long-term thesis, currently pulling back
python -m finance_bot.cli screen
```

Minimum path to reproduce the boards: `download` → `profile` → `daily` →
`screen`. (`graph`, `news`, `backtest` are independent and can lag.)

## 6. The math, exactly

Everything is derived from price history except news-tilt. The shared squasher
is `squash(x, scale) = tanh(x / scale)`, mapping any real number into `(−1, 1)`.

### 6.1 Structural long-term index (`analyze/profile.py`)

```
index = clip( 0.40·long_trend + 0.30·momentum + 0.15·stability + 0.15·news_tilt , −1, +1)
```
Weights live in `profile.WEIGHTS`. Components (all use only data ≤ `as_of`):

- **long_trend** — slope of a 200-day linear fit on **log** price, annualized:
  `squash(slope·252, scale=0.4)`. Direction of the multi-year path.
- **momentum** — 12-1 month momentum (skip the last month):
  `mom = close[−21]/close[−252] − 1`; `squash(mom, 0.5)`.
- **stability** — a *penalty* (≤ 0 in practice). With
  `dd = min(close/cummax − 1)` over 252d and annualized `vol`:
  `squash(−(|dd|·2 + max(0, vol − 0.4)), 1.0)`. Deep drawdown / high vol → more
  negative.
- **news_tilt** — credibility-weighted coverage in the last 30 days:
  `flow = Σ prior·recency_decay(age, 5d)`; `squash(flow, 4.0)`. **Currently ~0
  everywhere because the news store is essentially empty — the hook is wired but
  not fed** (see §8).

Buckets (`config.py`): `index ≥ +0.33 → +1`, `index ≤ −0.33 → −1`, else `~0`.

### 6.2 Daily driver (`analyze/daily.py`)

Each trading day, for every name:
```
event_delta = clip( Σ DAILY_WEIGHTS[k]·signal[k] , −DAY_CAP, +DAY_CAP)
live        = clip( prev + event_delta − REVERT·(prev − structural) , −1, +1)
```
`DAY_CAP = 0.06`, `REVERT = 0.04`. The `−REVERT·(prev−structural)` term is a
gentle daily pull back to the structural anchor, so if the tape goes quiet the
live index decays back to the thesis. Signals (`DAILY_WEIGHTS`):

| Signal | Weight | Definition |
|--------|--------|-----------|
| `day_move` | 0.035 | `squash(today_logret / vol20, 2.0)` × volume multiplier `clip(vol/avg20, 0.5, 2.0)` |
| `gap_shock` | 0.015 | `squash( ln(open/prev_close) / vol20 , 2.5)` |
| `range_break` | 0.020 | `+1` at a fresh 52-week high, `−1` at a fresh low, else `0` |
| `trend_shift` | 0.020 | `squash(ma50/ma200 − 1, 0.08)` |
| `news_tilt` | 0.030 | same credibility-weighted flow as §6.1 (0 until news is fed) |

Properties: **idempotent** per `(ticker, date)` (re-running a date is a no-op
unless `--force`), **point-in-time** (only bars ≤ run date), and **fully
logged** — `_daily_log.csv` records every signal value behind each move.

Seeding: the first time a ticker is seen, `live` starts at `structural`. To get
a realistic multi-day `live`, replay chronologically (reset `_daily_state.json`
and `_daily_log.csv`, then call `daily_update(as_of=d)` for each date in order).

### 6.3 Dip-in-uptrend screener (`analyze/screen.py`)

A candidate must pass three gates (`UP_GATE=0.33`, `MAX_PULLBACK=−0.30`,
`RECENT_HIGH_WIN=60`):
1. `structural_index ≥ 0.33` (strong long-term thesis)
2. `ret20 < 0` **and** price below its 50-day average (down now)
3. price above its 200-day average **and** pullback `> −30%` off the 60-day high
   (trend intact, not a falling knife)

Ranked by a transparent setup score:
```
setup      = 0.6·long_term + 0.4·st_quality
st_quality = 0.45·dip_depth + 0.30·oversold + 0.25·weakness
  dip_depth = clip(−pullback / 0.20, 0, 1)     # deeper dip (to −20%) scores higher
  oversold  = clip((55 − RSI14) / 30, 0, 1)     # RSI 25 → 1.0
  weakness  = clip(−ret20 / 0.15, 0, 1)         # −15% in 20d → 1.0
```

### 6.4 Backtest (`backtest/engine.py`)

- `event_study(events, close_matrix)` — for each event, forward simple returns
  at +1/+3/+5/+10 trading days from the event date.
- `reversal_stats(study)` — the *"don't panic"* metric: of names down at +1 day,
  what fraction recovered (≥ 0) by +5 days. High ⇒ single red days are noise ⇒
  require confirmation.
- `Backtest(close, events).run(signal)` — walk-forward long/flat sim; target
  weight capped at `MAX_TRADE_FRACTION` (5%); reports return, Sharpe, max
  drawdown vs. buy-and-hold. Signals: `trend_signal` (20/100 MA cross) and
  `make_news_aware_signal()` (trend × recent coverage flow; **never flips
  short** — that's the anti-panic design).

## 7. The visual boards (how they were built)

Three HTML artifacts were produced. All follow the **same repeatable recipe** —
no framework, no build step, self-contained single-file HTML:

1. **Prep script (Python).** Read `_summary.csv` / profiles / parquet, compute
   whatever the page needs (e.g. downsampled price series, CAGR, RSI), and dump
   a single JSON array to the scratchpad.
2. **HTML template.** Hand-written HTML+CSS+vanilla-JS with a literal
   `__DATA__` placeholder where the JSON gets injected. Charts are inline SVG
   drawn in JS from the embedded arrays (diverging bars, sparklines, a 5y line
   with a shaded pullback zone). Theming via CSS custom properties with
   light/dark handled through `prefers-color-scheme` **and**
   `:root[data-theme=...]`.
3. **Inject + publish.** `html.replace("__DATA__", json)` → write the file →
   publish as an Artifact (private URL) or just open locally.

The three boards:
- **Signal Board** — all 238 names, filterable by theme/verdict, diverging bar
  per name; Up names also show projected annual growth (5y CAGR + hot 200d
  trend).
- **Top 10** — highest-scoring names, each with a 5y chart, the four-component
  breakdown, and a written "why."
- **Dip in an Uptrend** — the screener output, spotlighting the #1 candidate
  with its pullback zone marked, plus the ranked table.

To rebuild a board: re-run its prep script (data changes daily), re-inject,
re-publish. Keep the same file path to keep the same Artifact URL.

> Projected-growth honesty note baked into the boards: a naive trend
> extrapolation explodes for parabolic names (e.g. "+1000%/yr"). The boards show
> the **5-year CAGR** as the credible figure and label the 200-day trend as
> momentum, not a target. Preserve that framing.

## 8. Tuning knobs (where to change behavior)

| Knob | File | Effect |
|------|------|--------|
| `THEMES` | `universe.py` | the entire investable universe + theme priors |
| `WEIGHTS` | `profile.py` | mix of the 4 structural components |
| squash `scale`s | `profile.py` | how quickly each component saturates |
| `LONG_TERM_UP/DOWN` | `config.py` | ±0.33 bucket thresholds |
| `DAILY_WEIGHTS`, `DAY_CAP`, `REVERT` | `daily.py` | daily nudge size & mean-reversion speed |
| `UP_GATE`, `MAX_PULLBACK`, `RECENT_HIGH_WIN` | `screen.py` | screener strictness |
| setup-score coefficients | `screen.py` | how candidates are ranked |
| `SOURCE_PRIOR` | `credibility.py` | per-outlet trust (edit by hand) |
| `corr_threshold`, `leadlag_threshold`, `max_lag` | `graph.py` | graph density |
| `MAX_TRADE_FRACTION`, `REQUIRE_MANUAL_CONFIRMATION` | `config.py` | **risk caps — do not weaken** |

## 9. Extension points

- **Wire news into the scores (biggest gap).** `news_tilt` is 0 because the
  event store is thin and the tilt is a coverage-*volume* proxy, not sentiment.
  To activate: run `news` regularly to accumulate `events.jsonl`, then replace
  the proxy in `profile._news_tilt` / `daily` with a real per-event sentiment
  score (an LLM or finance model). The credibility weighting
  (`influence = prior × corroboration × recency`) already exists to keep
  dishonest/lone-source news from dominating.
- **Add a news source.** Write one adapter class in `ingest/news.py` with a
  `.fetch()` returning `NewsEvent`s, register it in `collect()`. Paid feeds
  (Fox Business/WSJ transcripts) go here with your credentials — **do not scrape
  paywalled content.**
- **Have the daily driver flag new dip entries.** Cross-reference
  `screen.dip_in_uptrend()` inside `daily_update` and log when a name newly
  enters the dip state.
- **Schedule it.** Run `daily --download` each weekday after the close (cron /
  launchd / a scheduled task). Not yet automated — set it up deliberately.
- **Broker adapter.** Allowed only as a **manual-confirmation order preview** —
  it may draft an order for a human to approve; it must never auto-fire.

## 10. Known limitations & gotchas

- **"Long-term" = trend-based, not fundamental.** The index rewards names in
  strong recent uptrends (e.g. INTC's recovery run reads strongly "up"). It is
  not a valuation model. Say so wherever you present it.
- **News tilt is inert today.** Any claim that scores reflect news is currently
  false — only price drives them until §9 is done.
- **Trend extrapolation blows up.** Never present the annualized 200-day trend
  as a price target; use CAGR as the credible growth figure.
- **Correlations drift.** Graph edges are descriptive of history; the backtest,
  not the graph, tells you if an edge is tradable. Daily equity lead/lag is
  genuinely weak (|ρ|≈0.03) — treat leadlag edges as hints only.
- **Data recency.** `download` caches for 1 day; the daily driver needs fresh
  bars (`--download`) to actually advance a new session.
- **Survivorship / point-in-time universe.** `THEMES` is today's list; a true
  historical backtest would need the universe as it was in the past.

---

## 11. Safety boundaries (non-negotiable)

- **No trade execution, no fund movement.** Signals only; a human places orders.
- **`REQUIRE_MANUAL_CONFIRMATION = True`** and **`MAX_TRADE_FRACTION = 0.05`**
  are hard limits — do not remove or loosen them to "automate."
- **Not investment advice.** The `+1/~0/−1` index is a quantitative model output.
- **No paywall scraping / no ToS bypass.** Public feeds or licensed sources only.
